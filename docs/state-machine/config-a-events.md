use `T-xx` IDs (`config-a-transitions.md`), parameters use `P-xx` IDs

## Notes

- **Sources** are: *Onboard* (autonomous, generated by the FSM's own monitors/timers), *Ground* (uplinked command — always able to override per the Human-in-the-Loop governance requirement, section 3), *Scheduler* (the priority-queue scheduler, a distinct component from the FSM but feeding it mode-select events), *Fault-injection harness* (test/verification-only, used in Phase 3 W7 and simulated via `E-16` from any point including mid non-volatile write).
- `E-16 RESET` is deliberately the only event with no guard and no restricted source list in this table — it is the fault-injection harness's primary tool and must be dispatchable from any state without precondition. Its *effect* (what state the FSM lands in after reset) is guard-governed by the persistence layer, not by this event definition — see the transitions table's closed-world rule and the reset row.
